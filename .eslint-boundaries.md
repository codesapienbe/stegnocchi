# ESLint Module Boundary Rules

This document explains the import boundary rules enforced by ESLint to maintain the modular architecture.

## Module Architecture

```
├── core/          # Platform-agnostic business logic
├── web/           # Web-specific implementations
├── native/        # React Native-specific implementations  
├── api/           # Server/API functionality
├── cli/           # Command-line interface
├── platform/      # Abstraction layer (bridge between modules)
├── components/    # Shared UI components
├── screens/       # Application screens
├── utils/         # Shared utilities
└── types/         # Type definitions
```

## Boundary Rules

### 1. Core Module Isolation
**Rule**: Core cannot import from platform-specific modules
**Rationale**: Core contains business logic that must remain platform-agnostic

**Forbidden imports in `src/core/**/*`:**
- `src/web/**/*`
- `src/native/**/*` 
- `src/platform/**/*`
- `src/api/**/*`
- `src/cli/**/*`
- `src/components/**/*`
- `src/screens/**/*`
- `src/navigation/**/*`

**Allowed imports:**
- Node.js builtins
- External packages (must be platform-neutral)
- Other core modules
- Type definitions

### 2. Platform Module Separation
**Rule**: Platform modules cannot cross-import
**Rationale**: Prevents mixing platform-specific code

**Web module** (`src/web/**/*`) cannot import from:
- `src/native/**/*`
- `src/api/**/*` 
- `src/cli/**/*`

**Native module** (`src/native/**/*`) cannot import from:
- `src/web/**/*`
- `src/api/**/*`
- `src/cli/**/*`

**API module** (`src/api/**/*`) cannot import from:
- `src/web/**/*`
- `src/native/**/*`
- `src/cli/**/*`

**CLI module** (`src/cli/**/*`) cannot import from:
- `src/web/**/*`
- `src/native/**/*`
- `src/api/**/*`

### 3. UI Component Abstraction
**Rule**: UI components must use platform abstraction
**Rationale**: UI should work across platforms without direct platform imports

**Components** (`src/components/**/*`) cannot import from:
- `src/web/**/*` (use `@/platform` instead)
- `src/native/**/*` (use `@/platform` instead)

**Screens** (`src/screens/**/*`) cannot import from:
- `src/web/**/*` (use `@/platform` instead)
- `src/native/**/*` (use `@/platform` instead)

### 4. Utility Platform Neutrality
**Rule**: Utils must remain platform-agnostic
**Rationale**: Utilities should be reusable across all modules

**Utils** (`src/utils/**/*`) cannot import from:
- `src/web/**/*`
- `src/native/**/*`
- `src/api/**/*`
- `src/cli/**/*`

## Exceptions

### Platform Abstraction Layer
The `src/platform/**/*` module is exempt from boundary rules as it serves as the bridge between modules.

### Module Entry Points
Files named `index.ts` in module roots can re-export from internal modules.

### Development Tooling
Configuration files and development scripts can access any modules.

## Import Order

Imports must follow this order:
1. React and React Native
2. External dependencies  
3. Core modules (`@/core/**`)
4. Platform abstraction (`@/platform/**`)
5. Platform-specific modules (`@/web/**`, `@/native/**`, etc.)
6. Relative imports

## Validation

Run `npm run lint:boundaries` to check for boundary violations.

## Migration Guide

If you need to violate a boundary rule:

1. **Consider refactoring**: Can the code be moved to an appropriate module?
2. **Use dependency injection**: Pass platform-specific implementations to core logic
3. **Extend platform abstraction**: Add the required functionality to `@/platform`
4. **Create interfaces**: Define contracts in core, implement in platform modules

## Examples

### ✅ Good
```typescript
// In src/screens/MainScreen.tsx
import { PlatformAPI } from '@/platform';
const filePicker = PlatformAPI.useFilePicker();
```

### ❌ Bad  
```typescript
// In src/screens/MainScreen.tsx
import { pickFiles } from '@/web/utils/filePicker'; // Direct platform import
```

### ✅ Good
```typescript
// In src/core/crypto.ts
export interface FileHandler {
  saveFile(data: Uint8Array): Promise<string>;
}
```

### ❌ Bad
```typescript
// In src/core/crypto.ts
import { downloadFile } from '@/web/utils/fileDownload'; // Platform import in core
```
